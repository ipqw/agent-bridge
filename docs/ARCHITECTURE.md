# Agent Bridge — архитектура

## Задача

AI-агент работает на сервере: там его окружение, подписка и инструменты. Ему не хватает двух вещей —
программ, установленных на компьютере пользователя, и файлов пользователя: перекладывать их на сервер
долго, а иногда нельзя. Мост закрывает обе дыры, не перенося агента на компьютер: на компьютере стоит
приложение, которое даёт агенту контролируемые «руки» — терминал, браузер и офисные файлы.

## Компоненты

| Каталог | Что внутри |
|---|---|
| `app/` | Оболочка на Tauri 2: окно, трей, запуск и сторож Node-ядра, автозапуск |
| `core/src/` | Ядро: гейты MCP, политики, подтверждения, журнал, супервизор `frpc`, API окна |
| `core/ui/` | Окно на React: вкладки «Папки», «Программы», «Журнал», «Настройка» |
| `core/runtime/` | Python-часть офиса: `office_ops.py` (чтение, конвертация, пересчёт, рендер), `guard.py` (песочница скриптов), lock зависимостей с хешами |
| `vps/` | Серверная сторона туннеля: `frps` и `stcp`-visitor для окружения агента |
| `scripts/` | Скачивание закреплённого frp, подготовка ресурсов установщика, смоук-тест Windows |

**Гейт** (`core/src/gate.ts`) — HTTP-сервер MCP на `127.0.0.1`. Перед каждым вызовом инструмента
политика решает: выполнить сразу, спросить человека, отказать или ответить самой. Дочерний MCP-сервер
(terminal-mcp, playwright-mcp) получает только одобренные вызовы. У гейта `apps` дочернего сервера нет:
офисные инструменты — родные инструменты моста.

## Транспорт: frp `stcp`, не VPN

- Гейты слушают только `127.0.0.1`. `frpc` моста держит исходящее соединение к `frps` на сервере и
  отдаёт наружу только выбранные порты. Входящих портов на компьютере нет.
- Mesh-VPN отклонён: системный VPN-драйвер может конфликтовать с VPN, который у пользователя уже стоит,
  и открывает сети машину целиком, а не два-три порта.
- Каждый гейт получает постоянный порт по имени (`terminal`, `browser`, `apps`), поэтому выключение
  одного не сдвигает порты остальных. `frpc` перезапускается, только когда меняется его итоговый конфиг.

## Автозапуск

Обычная служба Windows живёт в session 0 и не видит рабочий стол — браузер и открытие файлов не
работали бы. Поэтому мост запускается в сессии пользователя: задача планировщика «при входе» с
перезапуском при падении (`core/src/autostart.ts`). Падение дочерних процессов ловит супервизор ядра,
падение самого моста — планировщик.

## Безопасность

Угроза прямая: агент читает интернет и документы, то есть недоверенный вход, а мост даёт ему руки на
компьютере с залогиненным браузером и файлами. Одна инъекция в странице — и агент может выполнить
команду. Поэтому модель — **allowlist + подтверждение человеком**.

1. **Защита в самом мосте, по умолчанию — запрет.** Каждый гейт отклоняет всё вне узкого списка
   (команды, папки, действия задаются в окне). Защита держится, даже если сервер агента взломан.
   Таймаут подтверждения — отказ.
2. **Терминал** (`core/src/allowlist.ts`, `policies/terminal.ts`). Строку shell нельзя проверить
   статически (пайпы, `Invoke-Expression`), поэтому безопасные команды разобраны по аргументам, всё
   остальное — карточка подтверждения. Enter и другие клавиши отправки тоже гейтятся.
3. **Папки.** Пути приводятся к реальным; запрещены `\\?\`, `\\.\`, UNC и альтернативные потоки NTFS.
   Внутри разрешённых папок — чтение без вопросов, вне — подтверждение.
4. **Браузер** (`policies/browser.ts`). Чтение и переходы по http(s) — сразу; клики, ввод, загрузки,
   скрипты — подтверждение; адреса не http(s) (`file:`, `chrome:`, `javascript:`, `data:`) — тоже подтверждение.
5. **Ключи.** `stcp` защищён секретом `sk`, уникальным на каждую установку: утечка одного ключа не даёт
   доступа к другим. Токены и ключи лежат в хранилище ОС (Windows Credential Manager), не в файлах.
6. **Недоверенный вход.** Содержимое страниц и документов не меняет поведение агента; инструкция
   внутри него — событие безопасности.

## Офисные файлы (гейт `apps`)

Код агента выполняется рядом с файлами, а агенту уходит только текст — как в локальных
AI-ассистентах, но с агентом на сервере.

**Окружение.** При включении мост скачивает `uv` с закреплённой версией и sha256, ставит CPython 3.12
и пакеты строго по lock-файлу с хешами (`core/runtime/office-requirements.txt`) в папку данных — без
прав администратора и без Python пользователя. CI проверяет ровно то окружение, что получит
пользователь.

**Инструменты.**

| Инструмент | Что делает |
|---|---|
| `office_read` | текст документа (markitdown), постранично по 64 КБ |
| `office_copy` | рабочая копия рядом с оригиналом: «Имя (правки агента).ext» |
| `office_convert` | `.doc` / `.xls` / `.ppt` → современные форматы и PDF |
| `office_recalc` | пересчёт формул, список ошибок по ячейкам |
| `office_render` | страницы и слайды в PNG, чтобы агент увидел результат |
| `office_run_python` | скрипт агента в песочнице |
| `office_propose` / `office_status` | отдать копию пользователю на проверку и узнать итог |

Пересчёт и рендер идут через Microsoft Office (COM, макросы принудительно выключены перед каждым
открытием), а без него — через LibreOffice, который мост ставит только с согласия пользователя. Все
вызовы Office и LibreOffice идут одной очередью. Книги с макросами Excel 4.0 отклоняются до открытия.

**Песочница скриптов** (`core/runtime/guard.py`). Два слоя:
- до запуска — разбор AST: импорт только из списка (openpyxl, python-docx, pandas и стандартные модули),
  запрещены `eval`, `exec`, `getattr`, имена и атрибуты с `_`;
- во время запуска — `sys.addaudithook`, запрещено всё, что не разрешено: чтение — только из
  разрешённых папок и окружения, запись — только в копии и новые файлы, никаких процессов, сети,
  `ctypes` и реестра. Запуск `python -I -B`, таймаут 120 с, при обрыве связи дерево процессов
  завершается.

Скрипт, не прошедший проверку, показывается пользователю карточкой с причиной простыми словами
(«хочет выйти в интернет») и кодом. Одобренный — выполняется без песочницы, как одобренная команда
терминала. Граница песочницы честная: она страхует от ошибок агента, а не от взломанного агента —
C-библиотека может писать мимо audit hook; это принятый риск.

**Правки.** Оригинал никогда не меняется скриптом. Агент правит копию и отдаёт её на проверку; при
«Заменить» мост переписывает оригинал через его же дескриптор (атрибуты и потоки сохраняются),
старую версию кладёт в резервную папку. Если оригинал изменился после создания копии, молча он не
перезаписывается.

## Метки в коде

Комментарии и тесты ссылаются на решения ревью (`D1`–`D9`), риски (`R6`–`R13`) и критерии приёмки
(`AC*`) дизайна офисной части. Основные:

| Метка | Суть |
|---|---|
| D1 | гейт `apps` без дочернего MCP, инструменты — родные |
| D3 | граница песочницы: страховка от ошибок, не от взлома |
| D4 | только Python, поставленный `uv`, никогда — Python пользователя |
| D5 | замена оригинала через его дескриптор, с резервной копией |
| D6 | изменённый после копии оригинал не перезаписывается молча |
| D7 | одобренный скрипт вне пула выполняется без песочницы |
| R6 | правила пула: импорт, чтение, запись, запрет процессов и сети |
| R7 | макросы выключены, Excel 4.0 отклоняется |
| R8 | таймаут и обрыв связи завершают всё дерево процессов |
| R9 | файлы, созданные агентом, регистрируются |
| R10 | `.doc` / `.ppt` — честная ошибка с советом сконвертировать |
| R13 | одна очередь на Office и LibreOffice |

## Тесты

`core/test/` — 12 наборов на `node:test`: allowlist и пути, политики гейтов, туннель `stcp` с
настоящим frp, песочница, офисные операции на реальных файлах, правки и замены, автозапуск Windows.
CI гоняет их на Ubuntu и Windows, затем собирает установщик и проверяет его смоук-тестом: установка,
старт, окно, гейты, автозапуск, принудительное завершение.
